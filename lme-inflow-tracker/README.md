# エルメ（L Message）QRコード別 流入計測 → スプレッドシート & Discord/Chatwork 毎日レポート

「エルメのQRコードアクション（流入経路分析）の流入件数を、APIでスプレッドシートに書き出し、
Zapier等でDiscord/Chatworkに毎日配信できるか？」の**調査結果**と、
**無料で実現する自作ツール（Google Apps Script）**のセットです。

調査日: 2026-08-10（出典はすべて文末。主にエルメ公式マニュアル lme.jp/manual）

---

## 結論（TL;DR）

| 質問 | 答え |
|---|---|
| エルメの公開APIで流入データを取れる？ | **公開REST APIは存在しない**。ただし代わりになる公式機能が3つある（下記） |
| ZapierでDiscord/Chatworkに出せる？ | **エルメの公式Zapierアプリは無い**。Zapier無料プランは「2ステップのみ・月100タスク・Webhooks有料」なので毎日サマリー配信は実質不可。やるならMake.com無料枠の方が向く |
| 毎日リマインド配信はできる？ | **できる。GAS（無料）だけで完結**するので、Zapier自体が不要。→ 同梱の `gas/コード.gs` |
| QRコード別の実登録数を自動記録できる？ | **できる可能性が高い**。エルメ公式「**パラメーターエクスポート**」= QRコードアクションの「**外部連携**」タブにコールバックURLを登録すると、**そのQR経由で友だち追加されるたびにエルメが外部へGET送信**してくれる。これをGASで受けてシートに記録する（本ツールの本命構成） |

## エルメから流入データを出す公式ルートは4つ

1. **パラメーターエクスポート（本命・自動/リアルタイム）**
   各QRコードアクションの編集画面「外部連携」タブでコールバックURLを登録すると、
   そのQR経由の友だち追加時に **LINE ID／友だち追加情報(new・old・block)／LINE登録名／
   メールアドレス＋URLに付与した任意パラメータ** をGETリクエストで外部システムに自動送信する。
   → 「QRコード別の実登録イベント」をリアルタイムに外部で記録できる唯一の公式手段。
   （注: 対応プランの明記が公式に無いため、管理画面に「外部連携」タブがあるかまず確認）

2. **スプレットシート連携（要・画面確認）**
   QRコードアクション一覧の「…」メニューに「スプレットシート連携」の項目が公式マニュアルに
   記載されている。ただし何がどう自動反映されるかの詳細マニュアルが見つからず未確認。
   エルメは別機能（フォーム回答・予約情報）ではGoogleスプレッドシートへの自動反映を公式提供
   しているので、QRコードアクションでも使えるならこれが最も手軽。**お使いの画面の「…」から
   一度試してみる価値あり**（もし流入データが自動でシートに入るなら、本ツールは「毎日配信」部分だけ使えばOK）。

3. **CSVダウンロード（手動）**
   QRコードアクション一覧・データ詳細画面からワンタッチでCSVダウンロード可。自動化は不可。
   また「友だち情報」のCSVエクスポートには**流入経路列を含められる**（どのQRから登録したか分かる）。

4. **エルメMCP（AI連携・読み取り）** — 2026年4月6日公開
   リモートMCPサーバー `https://mcp.lmes.jp/mcp` にChatGPT/Claudeを接続すると、
   **QRコードアクションの管理名・URL・総読み込み回数・経由フォロー数・日次統計**など
   約20カテゴリのデータを読み取れる（読み取り専用）。Claude Codeなら
   `claude mcp add --transport http lme https://mcp.lmes.jp/mcp` で接続を試せる
   （※Claude向け公式コネクタは2026年8月時点「審査中」表記のため、要動作確認）。
   「AIに『昨日のQR別流入まとめて』と聞く」使い方が今後の本命になりうる。

補足: エルメ純正の「通知設定」にはChatwork通知があるが**有料プラン限定**で、
1件ごとの通知のみ（QR別の日次サマリーは不可）。

## Zapier / Make の評価（2026年8月時点の無料枠）

- **Zapier無料**: 月100タスク／**2ステップZapのみ**／Webhooks by Zapierは**有料限定**／15分ポーリング。
  - エルメ公式アプリが無い＋Webhook受信不可のため、エルメ→Zapier直結は無料では組めない。
  - 唯一成立するのは「**Googleスプレッドシート新行 → Discord/Chatworkへ1件通知**」の2ステップ
    （本ツールやエルメのシート連携でシートに行が増える場合）。毎日サマリーはマルチステップになるため無料不可。
- **Make.com無料**: 月1,000オペレーション／15分間隔／シナリオ2件。**Webhook受信・分岐が無料**で使え、
  Chatwork(22モジュール)・Discord(32)・Google Sheets(27)の公式アプリあり。どうしてもノーコードで
  組みたいならZapierよりMake推奨。
- ただし**本ツール（GAS）はどちらも不要**で、集計〜毎日配信まで完結する。

## 参考: LINE公式アカウント純正だけでやる場合（エルメ不使用の代替）

- 管理画面の「友だち追加ガイド」で**計測パラメータ付きの友だち追加QR/URLを無料で発行**でき、
  ［分析］→［友だち］→［追加経路］で経路別追加数の確認とCSVダウンロードが可能。
- ただし **Messaging API（Insight API/followイベント）では経路別データは一切取得不可**（公式FAQ明記）、
  期間内20件未満の経路は非表示、表示は最大90日、ユーザー個人と経路の紐付け不可。
- → 「経路別にタグ付けしてセグメント配信」まで含めてやるなら、結局エルメ系ツールが必要。

# 自作ツールのセットアップ（所要 約20分・完全無料）

## 構成

```
[QRコード読取 → 友だち追加]
        │
        ▼
エルメ QRコードアクション ──(外部連携タブ: パラメーターエクスポート GET)──▶ GAS Webアプリ
                                                                            │ 記録
                                                                            ▼
                                                                   Googleスプレッドシート
                                                                            │ 毎日9時(変更可)
                                                                            ▼
                                                              Discord Webhook / Chatwork API
```

## 手順

### 1. スプレッドシート＋GASを用意
1. Googleスプレッドシートを新規作成（名前は自由。例「エルメQR流入ログ」）
2. メニュー「拡張機能」→「Apps Script」
3. エディタに `gas/コード.gs` の中身を全部貼り付け
4. （任意）プロジェクト設定 → 「appsscript.json をエディタで表示」をONにして `gas/appsscript.json` の内容に置き換え（タイムゾーンをAsia/Tokyoにするため。手動でタイムゾーン設定してもOK）

### 2. CONFIG を書き換え
- `QR_CODES`: 計測したいQRコードを列挙。`id` は自由な英数字（例 `affi_01`）、
  `name` は表示名、`url` はエルメのQRコードアクションで発行された友だち追加URL
  （「QRコードを表示」の下にあるURL。リダイレクタ方式を使わないなら未記入でも可）
- `DISCORD_WEBHOOK_URL`: Discordのチャンネル設定 → 連携サービス → ウェブフック作成でURLをコピー
- `CHATWORK_API_TOKEN` / `CHATWORK_ROOM_ID`: Chatwork右上の自分の名前 → サービス連携 → APIトークン。
  ルームIDはチャットURLの `#!rid` の後ろの数字
- どちらか片方だけでもOK（空欄の宛先には送信されない）

### 3. 初期化
- エディタ上部で関数 `setup` を選んで「実行」→ 権限を承認
- これでシート3枚（クリックログ/登録ログ/日次集計）と毎日のトリガーが作られる

### 4. Webアプリとしてデプロイ
1. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 「次のユーザーとして実行」= **自分** ／「アクセスできるユーザー」= **全員**
3. 発行された `https://script.google.com/macros/s/…/exec` をコピー

### 5. エルメ側に登録（2方式のどちらか）

**方式A（本命）: 外部連携タブにコールバックURLを登録**
各QRコードアクションの編集画面 →「外部連携」タブ → コールバックURLに
```
https://script.google.com/macros/s/…/exec?ev=reg&id=affi_01
```
を登録（QRコードごとに `id=` を変える）。以後、そのQR経由の友だち追加が
リアルタイムで「登録ログ」シートに記録される。**実際の友だち追加数**が取れるのでこちらを推奨。

**方式B（代替）: リダイレクタ方式**
「外部連携」タブが見当たらない場合はこちら。QRコードを
```
https://script.google.com/macros/s/…/exec?id=affi_01
```
から生成し直して配布する（QRコード画像は任意の無料QR生成サービスでOK）。
読み取り→エルメの友だち追加URLへ自動転送しつつ「クリックログ」に記録される。
※計測できるのは読み取り(クリック)数で、実際に友だち追加したかまでは分からない。
※遷移時に1〜3秒の「移動しています…」画面を挟む。既に配布済みのQRコードには使えない
（印刷物を作り直す前提の方式）。

### 6. テスト
- ブラウザで `…/exec?ev=reg&id=affi_01` を開く →「登録ログ」に1行増えればOK（テスト行は消してよい）
- エディタで `testReport` を実行 → DiscordやChatworkにレポートが届けばOK
- 以後、毎日 `REPORT_HOUR` 時（初期値9時）に自動配信される（GASトリガーの仕様上、最大±15分程度ずれる）

## 制限・注意

- **無料枠は余裕**: GAS無料枠はUrlFetch 20,000回/日・トリガー実行90分/日。1日1回の配信＋流入記録なら1%も使わない。Discord Webhook・Chatwork APIも無料（Chatworkは組織管理下のアカウントだと管理者承認が要る場合あり）。
- パラメーターエクスポートで送られてくるのは**LINE IDなどの個人データを含む**。スプレッドシートの共有範囲に注意（リンク共有はオフ推奨）。
- 「外部連携」タブの対応プランは公式に明記がない。フリープランで表示されない場合は方式Bか、前述の「スプレットシート連携」「CSVダウンロード」を利用。
- エルメ側の管理画面の数字が正（本ツールはあくまで自前の控え）。ブロック等のイベントも登録ログに混ざる場合があるため、厳密な突き合わせはエルメのデータ詳細で。
