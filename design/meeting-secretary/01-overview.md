# 01. プロダクト概要・要件定義

## 1. プロダクトビジョン

**「打ち合わせの秘書」**。ユーザーは会議に出るだけ。それ以外の全て——参加、録画、議事録、タスク管理、共有、整理、進捗把握、次回準備——をアプリが担う。

tl.dv / Fireflies / Otter との差別化ポイントは **「事業（プロジェクト）軸での自動整理と進捗生成」**。既存ツールは「1会議の記録」で終わるが、本アプリは会議を事業に紐付けて時系列で束ね、**事業の現在地と次の一手（NA）** を出す。

## 2. ペルソナ

| ペルソナ | 状況 | 課題 |
|---|---|---|
| 複数事業を持つ経営者・事業責任者（メイン） | 1日に複数の打ち合わせ。事業A/B/Cを並行運営 | 議事録が追いつかない、決定事項・宿題が流れる、事業ごとの進捗が頭の中にしかない |
| PM / 営業マネージャー | クライアント別・案件別に会議が発生 | 案件フォルダ整理と共有が手作業。次回アジェンダ作成が毎回ゼロから |
| チームメンバー | 会議に出られないことがある | あとから要点だけ知りたい。自分のタスクだけ知りたい |

## 3. 機能要件

### 3.1 会議の検知と自動入室

- **F-01** Google カレンダー連携（OAuth）。予定から Google Meet / Zoom の会議 URL を抽出し、入室スケジュールを自動登録する。
- **F-02** Zoom 連携（OAuth + Webhook）。`meeting.started` イベントで **予定外・突発の会議** も検知する。
- **F-03** 会議開始時刻にボットが自動入室する（Meet / Zoom 両対応）。待機室で承認待ちができ、N分承認されない場合はホストに通知する。
- **F-04** 入室ポリシー設定: 「全会議に参加 / 自分が主催の会議のみ / 社内のみ / 特定カレンダーのみ / 除外リスト」をワークスペース・ユーザー単位で設定できる。
- **F-05** 手動招待のフォールバック: 会議 URL の貼り付け、またはボット用メールアドレスをカレンダー招待に追加することでも参加できる。
- **F-06** 録音に関する同意表示: ボットは入室時に名前（例「〇〇 議事録Bot」）とチャットメッセージで録画中であることを明示する。

### 3.2 録画・文字起こし

- **F-10** 会議の映像+音声を録画し、会議終了後に自動でクラウド保存する（mp4 / 音声のみ mp3）。
- **F-11** 話者分離（ダイアライゼーション）付き文字起こし。参加者名とのマッピングを行う（発話中のアクティブスピーカー情報を利用）。
- **F-12** 日本語・英語の混在会議に対応。専門用語のカスタム辞書（ワークスペース単位）を登録できる。
- **F-13** 録画プレイヤー上でトランスクリプトをクリックすると該当時刻へジャンプできる。

### 3.3 議事録・タスク・NA の自動生成

- **F-20** 会議終了後 10 分以内に議事録を自動生成する。構成: 概要 / 決定事項 / 論点と結論 / 保留事項 / タスク / 次回アジェンダ案（NA）。
- **F-21** タスク抽出: 担当者・期限・根拠となる発言（タイムスタンプリンク付き）を構造化して抽出する。
- **F-22** NA（Next Action / 次回アジェンダ）生成: 今回の保留事項 + 未完了タスク + 前回からの持ち越しを踏まえた次回の論点案を生成する。
- **F-23** 次回会議の事前ブリーフ: 同一事業の次の会議の前（例: 1時間前）に「前回の決定事項・宿題の消化状況・今回のアジェンダ案」を参加者に自動送付する。
- **F-24** 議事録は編集可能。編集履歴を保持する。

### 3.4 事業（プロジェクト）管理と自動整理

- **F-30** 「事業」を登録できる（名前、説明、キーワード、関係者、関連ドメイン、紐付く Slack チャンネル / Drive フォルダ）。
- **F-31** 会議を事業へ自動分類する（タイトル・参加者・内容から LLM が判定）。確信度が低い場合は「未分類インボックス」に入れ、ユーザーの手動振り分けを学習に反映する。
- **F-32** 事業ごとのフォルダビュー: 会議（録画・議事録）が事業別・時系列に整理される。Google Drive / Notion への自動エクスポート先も事業単位で設定できる。
- **F-33** 事業ダッシュボード: 会議数、未完了/完了タスク、決定事項タイムライン、直近の NA を一覧できる。
- **F-34** 事業進捗レポート: 週次（設定可）で「今週の動き・決定事項・進捗・リスク・来週やること」を LLM が事業横断の会議履歴から生成し、Slack / メールに配信する。

### 3.5 共有・配信

- **F-40** 共有リンクの自動発行: 会議ごとに録画+議事録の共有ページ URL を生成する。オプション: 有効期限、パスワード、ワークスペース外への公開可否、議事録のみ/録画込みの範囲指定。
- **F-41** 会議終了後の自動通知: 参加者へメール、事業に紐付く Slack チャンネルへ議事録サマリ+リンクを自動投稿する。
- **F-42** タスクの外部連携（Phase 2 以降）: Notion / Asana / Linear へのタスク同期。

### 3.6 検索・横断機能（Phase 3）

- **F-50** 全会議横断のセマンティック検索（「A社との値決めの話いつだっけ？」→ 該当発言+動画位置）。
- **F-51** 事業をまたいだ質問応答（RAG）: 「事業Xの直近の課題は？」に会議履歴から回答する。

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 同時録画数 | MVP: 同時 10 会議 / 将来: 水平スケール（1会議=1コンテナで線形スケール） |
| 処理時間 | 会議終了 → 議事録配信まで p95 で 10 分以内（60分会議想定） |
| 可用性 | ボット入室成功率 98% 以上を KPI とし、失敗時は 2 分以内にホストへ通知 |
| セキュリティ | 保存時暗号化（S3 SSE-KMS）、通信 TLS、OAuth トークンは KMS 封筒暗号化で保管、監査ログ |
| プライバシー / 法令 | 録画同意の明示（入室名 + チャット告知 + 参加者向け事前通知オプション）。日本では当事者録音は適法だが、対外会議向けに「同意確認モード」を用意。データ保持期間・削除ポリシーをワークスペース単位で設定可能 |
| データ分離 | ワークスペース単位のマルチテナント。RBAC（Owner / Admin / Member / Guest） |
| コスト | 録画 1 時間あたりの変動費を可視化し、プラン設計に反映（06 参照） |

## 5. スコープ外（当面やらないこと）

- Microsoft Teams 対応（アーキテクチャ上は Provider 追加で対応可能な設計にするが、MVP では対象外）
- リアルタイム字幕・リアルタイム議事録（終了後バッチ処理を優先。パイプラインはストリーミング化可能な構成にしておく）
- モバイルネイティブアプリ（Web レスポンシブで代替）
