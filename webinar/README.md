# 説明会ウェビナーシステム（予約サイト × 公式LINE × 疑似ライブ配信）

オンライン説明会の **予約サイト** と **LINE公式アカウント** を連携し、
**開催当日の3時間前に視聴リンクを自動送信**。参加者は届いたリンクを開くだけで、
**開始時刻になると自動で映像が始まる**（Zoom不要）システムです。

> 「Zoomの入り方が分からない」で離脱していた人を取りこぼさないことが目的です。
> 参加者の操作は「LINEに届いたボタンを押す」だけになります。

**Cloudflare Workers の無料プランで、サーバー代0円のまま運用できます。**
手元の Node.js でもそのまま動くので、開発と検証はローカルで完結します。

## 1. 何ができるか

### 参加者から見た流れ

| | 参加者がすること | システムがすること |
|---|---|---|
| ① | 予約サイトで日時を選び、名前を入力 | 予約を受け付け、6文字の予約コードを表示 |
| ② | 「LINEを開いて連携する」を1タップ | 友だち追加＋コード送信が同時に完了 → 予約と紐づけ |
| ③ | （待つだけ） | **前日** にリマインド／**3時間前に視聴リンク**／**10分前**に直前リマインド |
| ④ | LINEのボタンを押す | 視聴ページが開き、開始時刻まではカウントダウン |
| ⑤ | （待つだけ） | **開始時刻になると自動で再生開始** |

インストール不要・ログイン不要・アプリ不要。スマホのブラウザだけで完結します。

### 運営者から見た機能

- **開催枠の管理** … 単発の追加と、「毎週 月〜金 20:00」のような**定期開催ルール**（枠が自動生成され続けるエバーグリーン運用）
- **予約管理** … 一覧・LINE連携状況・視聴到達時間・CSV書き出し
- **通知の可視化** … いつ何を送ったか／送信待ち／失敗と手動再送
- **視聴分析** … 開始・離脱・CTAクリックの記録
- **質問の受付** … 視聴中に届いた質問を管理画面で確認
- **申し込みボタン（CTA）** … 再生から指定した時間が経つと画面に出現

## 2. 仕組み

### 3時間前の通知（アウトボックス方式）

予約が LINE と連携された時点で、送信予定を**先にデータベースへ積みます**。
ワーカーが20秒ごとに「送信時刻が来たもの」を取り出して送信します。

```
予約 → LINE連携
   ├─ 予約完了通知 ………………… すぐ
   ├─ 前日リマインド …………… 開始24時間前
   ├─ ★視聴リンク ……………… 開始3時間前   ← 本システムの中核
   └─ 直前リマインド ………… 開始10分前
```

- **プロセスが落ちても予定は消えません**（DBに残っているため、再起動後に送信されます）
- **駆け込み予約にも対応**します。開始2時間前に予約した人には、視聴リンクが**その場ですぐ**届きます
- 同じ予約・同じ種類の通知は**一意制約で二重送信されません**
- 送信失敗は 30秒 → 2分 → 10分 → 30分 と間隔を空けて再試行し、
  ブロックされている等の恒久的なエラーは即座に打ち切ります

### 疑似ライブ（simulive）配信

録画済みの動画を、**開始時刻に合わせて全員同じ位置で**再生します。

```
再生位置 = 現在時刻 − 開始時刻
```

これだけの原理ですが、結果として次が成り立ちます。

- 20:00開始の回を 20:12 に開いた人は、**12分の位置から**始まる（＝本当の生配信と同じ）
- **巻き戻し・早送りができない**（シーク操作はサーバー時刻の位置へ戻されます）
- **開始前に動画URLを渡さない**ので、先に全部見られてしまうことがありません
- 通信が切れても、リロードすれば**現在の位置から復帰**します

スマホのブラウザは音声つき自動再生を禁止しているため、
**まずミュートで再生を始め、「🔊 音声をオンにする」ボタン**を大きく表示します。

## 3. 5分で動かす

まずは手元で動かして、感触を確かめてください。
必要なもの: **Node.js 22.5 以上**（実行時の依存パッケージはゼロ。`npm install` は不要です）

```bash
cd webinar

# 1. 設定ファイルを用意
cp .env.example .env
# .env を開いて ADMIN_PASS と SESSION_SECRET を必ず変更してください
#   SESSION_SECRET の生成例:  openssl rand -hex 32

# 2. サンプルデータを入れる（任意）
npm run seed

# 3. 起動
npm start
```

| URL | 内容 |
|---|---|
| http://localhost:3000/ | 予約サイト |
| http://localhost:3000/admin | 管理画面 |
| http://localhost:3000/line/webhook | LINEのWebhook受け口 |

LINEのアクセストークン未設定のときは **ドライラン** で動きます
（実送信せず、管理画面の「通知」タブと `outbound_log` テーブルに内容が記録されます）。
LINEの設定前でも、予約から視聴までの流れをひととおり試せます。

```bash
npm test    # 60件のテストが通ることを確認できます
```

## 4. LINE公式アカウントの設定

[LINE Developers コンソール](https://developers.line.biz/console/) で **Messaging API チャネル** を作成し、
次の3つを `.env` に設定します。

| .env の項目 | 取得場所 |
|---|---|
| `LINE_CHANNEL_SECRET` | チャネル基本設定 → チャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | Messaging API設定 → チャネルアクセストークン（長期）を発行 |
| `LINE_BASIC_ID` | Messaging API設定 → ボットのベーシックID（`@` から始まる文字列） |

### Webhookの設定

1. **Messaging API設定 → Webhook URL** に `https://あなたのドメイン/line/webhook` を設定
2. **Webhookの利用** を **オン**
3. 「検証」ボタンを押して成功することを確認（`https` である必要があります）

### 応答設定（重要）

**Messaging API設定 → 応答メッセージ を「オフ」** にしてください。
オンのままだと、LINE標準の自動応答が先に返ってしまい、予約コードの連携メッセージが埋もれます。

| 項目 | 設定 |
|---|---|
| 応答メッセージ | **オフ** |
| あいさつメッセージ | オフ（本システムが友だち追加時に案内を送るため） |
| Webhook | **オン** |

### 参加者がLINEに送れる言葉

| 送信内容 | 応答 |
|---|---|
| 予約コード（6文字） | 予約と連携し、確認メッセージを返す |
| 「予約」「日程」「申込」 | 開催日程を案内 |
| 「確認」 | 現在の予約内容を表示 |
| 「キャンセル」 | 予約の取り消しページを案内 |
| 「ヘルプ」 | 使い方を案内 |
| それ以外 | **自動応答しません**（担当者が手動で返信できる状態を保つため） |

## 5. 動画の用意

管理画面の「コンテンツ」タブで、次の3つの書き方から選べます。

### ① YouTube の限定公開動画（いちばん手軽・推奨）

```
youtube:dQw4w9WgXcQ
```

動画の置き場所を用意する必要がなく、通信量の負担もありません。
YouTube に **「限定公開」** でアップロードし、URL の `v=` の後ろを指定します。

- 操作バーは非表示にし、クリックも無効化しています（YouTubeへ離脱させません）
- 「限定公開」はURLを知っていれば誰でも見られます。URLが漏れて困る内容には向きません

### ② 自前のMP4ファイル

```
file:seminar.mp4
```

`webinar/media/` に置いた動画を配信します。Rangeリクエストに対応しているので、
途中からの読み込みも問題ありません。**配信時間中しか取得できません**（それ以外は 403）。

> ⚠️ この方式は **Node.js で動かす場合のみ**です。Cloudflare Workers はディスクを持たないため
> 501 を返します。無料運用したい場合は ① か ③ を選んでください。

### ③ CDN / S3 のURL

```
https://cdn.example.com/seminar.mp4
```

配信時間中だけ、そのURLへリダイレクトします。
より厳密にしたい場合は `src/routes/watch.js` の `/watch/:token/media` で
CloudFront や S3 の**署名付きURL**を都度発行する実装に差し替えてください。

> **本編の長さ（分）は、動画の実尺と必ず揃えてください。** この長さを過ぎると「終了」表示になります。

## 6. 運用の流れ

### 初回だけ

1. 管理画面 → **コンテンツ** タブで説明会を1件登録（タイトル・動画・長さ・CTA）
2. 管理画面 → **開催枠** タブで **定期開催ルール** を作成
   （例: 月〜金 / 20:00 / 定員30名 / 14日先まで）
   → 以後、開催枠が自動で作られ続けます

### 毎日

やることはありません。予約・通知・配信は自動で回ります。

### ときどき確認すること

| 見る場所 | 何を見るか |
|---|---|
| ダッシュボード | **LINE連携率**。低い場合は予約完了ページの導線を見直す |
| 通知タブ | **送信失敗** が無いか。あれば「再送する」で復旧できます |
| 予約タブ | 視聴到達時間。CSVで書き出して分析できます |
| 質問タブ | 視聴中に届いた質問。公式LINEから個別に回答します |

### 予約したのに視聴リンクが届かない人がいたら

ほぼ **LINE連携が済んでいない**（予約コードを送っていない）ケースです。
予約タブで「未連携」になっていないか確認してください。
連携が無い相手にはLINEを送る手段が無いため、通知は積まれません。
その場合は、予約時のメールアドレス宛に `予約確認ページ`（`/r/<トークン>`）をお伝えください。

## 7. 本番環境へのデプロイ（無料）

### なぜ Cloudflare Workers なのか

本システムは「開催3時間前に必ず送信する」ため、**止まらない実行環境**が要ります。
無料で使える候補を比べると、実質これ一択でした。

| 候補 | 判定 |
|---|---|
| Render 無料 | 15分で停止し、**無料プランに永続ディスクが無い** → 通知が飛ばず予約も消える ✗ |
| Fly.io | 2026年に新規の無料枠が廃止 ✗ |
| Oracle Cloud 無料VM | 7日間CPU20%未満で**インスタンスを回収**される → 低負荷の本アプリは消される ✗ |
| **Cloudflare Workers + D1** | 10万リクエスト/日・**1分ごとのCron**・DB 5GB・停止なし・クレジットカード不要 ✓ |

無料プランの上限（10万リクエスト/日、D1 は 5GB・500万行読み取り/日）に対し、
本システムの想定利用（1日100人が45分視聴しても1万リクエスト程度）は十分に収まります。

> **Workers では動画の自前配信ができません**（ディスクを持たないため）。
> 動画は **YouTube限定公開** か **CDNのURL** を使ってください（`file:` 指定は 501 を返します）。
> 自前ファイルを配信したい場合は、下の「Node.js で動かす場合」を選んでください。

### 手順（30分ほど）

```bash
cd webinar
npm install          # wrangler（デプロイ用ツール）だけを入れます

# 1. Cloudflare にログイン（ブラウザが開きます。カード登録は不要）
npx wrangler login

# 2. データベースを作る → 出力された database_id を wrangler.toml に貼る
npm run cf:db:create

# 3. テーブルを作る
npm run cf:db:init

# 4. 秘密の値を登録する（画面に貼り付ける形で聞かれます）
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
npx wrangler secret put LINE_CHANNEL_SECRET
npx wrangler secret put ADMIN_PASS
npx wrangler secret put SESSION_SECRET     # openssl rand -hex 32 で生成した値

# 5. 公開する
npm run cf:deploy
```

デプロイすると `https://antai-webinar.＜あなたのサブドメイン＞.workers.dev` が払い出されます。

**最後に必ず2つ:**
1. `wrangler.toml` の `[vars] BASE_URL` を、払い出されたURLに書き換えて `npm run cf:deploy` をやり直す
   （このURLを元に、LINEに送る視聴リンクを組み立てているため）
2. LINE Developers の Webhook URL に `https://＜払い出されたURL＞/line/webhook` を設定して「検証」

`[vars] LINE_BASIC_ID` も忘れずに埋めてください（1タップ連携リンクの生成に使います）。

### ローカルでCloudflare版を確認する

```bash
npx wrangler d1 execute antai-webinar --local --file=src/schema.sql   # 初回のみ
npm run cf:dev     # → http://localhost:8788
```

`.dev.vars` に環境変数を書いておけば、本番と同じ構成のまま手元で試せます。
Cron（通知送信）を手で動かすには `http://localhost:8788/cdn-cgi/handler/scheduled?cron=*+*+*+*+*` を開きます。

### 運用コマンド

```bash
npm run cf:logs                                             # 稼働中のログを見る
npx wrangler d1 execute antai-webinar --remote --command "SELECT COUNT(*) FROM reservations"
npx wrangler d1 export antai-webinar --remote --output backup.sql   # バックアップ
```

D1のバックアップは月1回ほど手元に保存しておくことをおすすめします。

### 独自ドメインを使う場合

Cloudflare にドメインを追加し、**Workers & Pages → 対象のWorker → 設定 → ドメインとルート**
からカスタムドメインを追加します。追加後に `BASE_URL` を書き換えて再デプロイしてください。

### Node.js で動かす場合（自前サーバー・動画も自前配信したいとき）

同じコードが Node.js でも動きます。**動画ファイルの自前配信（`file:` 指定）が必要な場合はこちら**です。
ただし常時起動できるサーバー（有料のVPSやPaaS）が要ります。

**Docker:**

```bash
docker build -t antai-webinar .
docker run -d --name webinar -p 3000:3000 --env-file .env \
  -v $(pwd)/data:/app/data -v $(pwd)/media:/app/media antai-webinar
```

`data/`（データベース）と `media/`（動画）は**必ず永続化**してください。

**systemd:**

```ini
# /etc/systemd/system/webinar.service
[Unit]
Description=ANTAI Webinar
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/webinar
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning src/server.js
Restart=always
RestartSec=5
EnvironmentFile=/opt/webinar/.env

[Install]
WantedBy=multi-user.target
```

nginx などのリバースプロキシで https 終端し、`/` をこのアプリへ渡してください。
バックアップは `data/webinar.db` をコピーするだけです（SQLite）。

```bash
sqlite3 /opt/webinar/data/webinar.db ".backup '/backup/webinar-$(date +%F).db'"
```

## 8. 法令上の注意（重要）

本システムは **「開始時刻の決まった録画配信」** です。生放送ではありません。
この事実を隠さない範囲であれば、疑似ライブ配信そのものに問題はありません。
視聴ページの下部には、常に次の注記を表示しています。

> この配信は、ご予約いただいた開始時刻に合わせて自動再生される録画配信です。

一方、次の2つの演出は **既定でオフ** にしてあります。

| 機能 | リスク |
|---|---|
| 視聴者数の表示 | 実際の同時視聴者数と異なる数字を「参加者数」として見せると、景品表示法上の**優良誤認・有利誤認**と判断されるおそれがあります |
| コメント欄（台本） | 実在しない参加者の発言を本物のように見せる行為は、同様のリスクに加え、**ステルスマーケティング規制**（2023年10月〜）にも触れうる領域です |

使う場合は、次のいずれかを推奨します。

- **視聴者数** … 実測値のみを表示する（管理画面で「目安人数」を0にすると実測のみになります）
- **コメント欄** … 主催者（司会）の進行アナウンスだけに限定し、参加者を装った発言を入れない

> アンタイ（ANTAI）は「誠実・透明・正確」を差別化の核としています
> （`ANTAI-サイト-引き継ぎ.md` の設計思想を参照）。
> 短期のCVRのために、その資産を毀損しないことをおすすめします。

### 個人情報

予約時に取得するのは氏名・メール・電話・LINEユーザーIDです。
プライバシーポリシー（`docs/privacy.html`）の記載範囲と齟齬がないかご確認ください。

## 9. 設定項目の一覧

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `BASE_URL` | `http://localhost:3000` | **公開URL**。LINEに送るリンクの組み立てに使う。本番では必ずhttps |
| `PORT` | `3000` | 待ち受けポート |
| `LINE_CHANNEL_ACCESS_TOKEN` | （空） | 空だとドライラン（実送信しない） |
| `LINE_CHANNEL_SECRET` | （空） | 空だとWebhookを受け付けない |
| `LINE_BASIC_ID` | （空） | `@` から始まるベーシックID。1タップ連携リンクの生成に必要 |
| `LINE_ADD_FRIEND_URL` | 自動生成 | `https://lin.ee/xxxx` 形式の友だち追加URL |
| `ADMIN_USER` / `ADMIN_PASS` | `admin` / （空） | 管理画面のログイン。**必ず変更** |
| `SESSION_SECRET` | （空） | Cookie署名用。**必ず変更**（`openssl rand -hex 32`） |
| `DB_PATH` | `./data/webinar.db` | SQLiteの保存先 |
| `MEDIA_DIR` | `./media` | `file:` 指定の動画の置き場所 |
| `NOTIFY_CONFIRM` | `on` | 予約完了通知 |
| `NOTIFY_REMIND_1D` | `on` | 前日リマインド |
| `NOTIFY_REMIND_10M` | `on` | 10分前リマインド |
| `NOTIFY_START` | `off` | 開始通知 |
| `NOTIFY_FOLLOWUP` | `off` | 終了30分後のフォローアップ |
| `WORKER_INTERVAL_MS` | `20000` | 通知ワーカーの巡回間隔（Node版のみ。Cloudflare版はCronが1分ごと） |
| `MAX_SENDS_PER_RUN` | `40` | 1回の実行で送る上限（Workers無料プランのサブリクエスト上限50に収めるため） |

> **3時間前の視聴リンク送信は本システムの中核要件のため、オフにできません。**

## 10. 困ったときは

| 症状 | 原因と対処 |
|---|---|
| LINEに何も届かない | ①`LINE_CHANNEL_ACCESS_TOKEN` が未設定（ドライラン）②予約タブでLINE「未連携」になっている ③管理画面の通知タブで失敗理由を確認 |
| Webhookの「検証」が失敗する | `BASE_URL` がhttpsか／`LINE_CHANNEL_SECRET` が正しいか／サーバーが外部から到達可能か |
| 予約コードを送っても反応がない | LINE側の**応答メッセージがオン**になっていませんか（オフにしてください） |
| メッセージが飾りのない文字だけになる | `BASE_URL` がhttpsでないためテキストに退避しています。https化してください |
| 動画が再生されない | ①本編の長さと動画の実尺が合っているか ②`file:` 指定のファイルが `media/` にあるか ③配信時間外は仕様上403です |
| 音が出ない | ブラウザの制限でミュート開始します。「🔊 音声をオンにする」を押してください |
| 再生位置がずれる | 5秒ごとにサーバー時刻へ自動補正します。大きくずれる場合はサーバーの時刻同期（NTP）を確認してください |
| 再起動したら通知が飛ばない | 通知はDBに残るため消えません。起動後の巡回（Node版は最大20秒、Cloudflare版は最大1分）で送信されます |
| Cloudflare版で動画が501になる | `file:` 指定は Workers では使えません。`youtube:動画ID` かCDNのURLに変えてください |
| Cloudflare版でCronが動かない | `npm run cf:logs` でログを確認。`wrangler.toml` の `[triggers] crons` が設定されているかも確認 |
| 「1027」エラーが出る | Workers無料プランの1日10万リクエストを超えました（翌0時UTCに復帰）。通常運用ではまず到達しません |

ログはすべて標準出力に出ます（`docker logs` / `journalctl -u webinar`）。
